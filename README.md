# 🏪 通用门店运营分层诊断系统

基于 Streamlit 的通用门店运营数据分析与分层诊断工具：上传门店运营数据，自动完成字段标准化、数据清洗与异常检测，并从「营收规模、获客能力、转化效率、客群质量、渠道健康度」五个维度对门店进行 **S / A / B / C 分层**，输出逐店诊断结论与可落地建议。

当前版本：**v0.3.0**

## ✨ 功能特性

- **双页面导航**：侧边栏「数据导入」与「分析诊断」两页切换，操作流程清晰
- **灵活的数据导入**：
  - 支持 CSV / XLSX（单文件 ≤ 20MB）
  - 拖拽式字段映射：将业务列名映射到 5 个标准字段（门店名称、获客数量、到店数量、成交人数、销售额），自动推荐映射、支持别名标准化
  - 客单价为派生字段，由系统按 `销售额 ÷ 成交人数` 自动计算，无需映射
- **数据清洗与异常检测**：
  - 数值异常（缺失、零值、负值）自动标记
  - 口径自动修正（如「成交人数 > 到店数量」「到店数量 > 获客数量」时按业务漏斗关系自动修正，并写入「数据异常标记」列）
- **一键体验**：内置 15 家模拟门店示例数据（`data/example_data.csv`），点击「加载示例数据」即可跑通完整流程
- **五维加权分层模型**：营收规模 25% / 获客能力 20% / 转化效率 25% / 客群质量 15% / 渠道健康度 15%，按排名比例分界输出 S / A / B / C 四级
- **多级标签诊断**：渠道标签（渠道单一型、转介绍驱动型等）、客群标签（老客复购型、高净值型等）、问题标签（获客不足、转化低效、渠道畸形等），并配套可落地的运营建议库
- **配置驱动**：所有业务口径（字段体系、分层模型、诊断规则、建议库、主题配色）集中在 `utils/config.py`，换零售业态只需改配置，并在启动时自动校验配置一致性

## 🚀 快速开始

### 环境要求

- Python 3.12+（已验证环境：Python 3.12.4 / Anaconda）
- 依赖见 [requirements.txt](requirements.txt)（版本已对齐本机验证环境，可复现）

### 安装与运行

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 启动应用
streamlit run app.py
```

浏览器自动打开后即可使用（默认 `http://localhost:8501`）。

> 本机 Python 安装在 Anaconda 时，可显式使用 `/d/Anaconda/python.exe -m streamlit run app.py` 运行。

### 使用流程

1. **数据导入页**：上传 CSV / XLSX 文件 → 按提示完成 5 个必填标准字段的映射（可手动调整自动推荐）→ 点击「确认映射并清洗数据」
2. 也可直接点击「✨ 加载示例数据」跳过上传，一键体验完整流程
3. **分析诊断页**：系统自动完成指标计算 → 门店分层 → 报告生成，输出大盘概览与逐店诊断结果
4. 数据上传错误或映射调整后，可使用「🗑️ 清空当前数据」重置

## 🛠️ 核心模块说明

| 模块 | 职责 |
| --- | --- |
| `utils/config.py` | **业务配置单一事实源**：标准字段 / 渠道字段 / 客群字段、分层模型（五维权重、分级分界）、诊断规则与建议库、应用主题。改配置即换业态 |
| `utils/data_process.py` | 文件读取（CSV / XLSX）、字段映射与别名标准化、数据清洗、异常标记与口径修正 |
| `utils/metrics.py` | 计算转化率（到店 / 成交 / 总转化）、客单价、渠道丰富度、优质渠道占比、客群占比等指标 |
| `utils/leveling.py` | 五维加权评分 → S / A / B / C 分层；渠道 / 客群 / 问题标签判定 |
| `utils/report.py` | 大盘概览与逐店诊断报告（分层分布、命中问题、优势与建议） |

### 分层模型（一级五维 + 二级标签）

- **五维加权评分**：营收规模（25%）+ 获客能力（20%）+ 转化效率（25%）+ 客群质量（15%）+ 渠道健康度（15%）
- **分级分界**：S（前 20%）/ A（前 50%）/ B（前 80%）/ C（剩余）
- **二级标签**：渠道标签（如「转介绍驱动型」「渠道单一型」）、客群标签（如「老客复购型」「高净值型」）、问题标签（如「获客不足」「转化低效」「渠道畸形」）

### 数据口径

**5 个必填标准字段**（映射后才可完成完整诊断）：

| 标准字段 | 用途 |
| --- | --- |
| 门店名称 | 门店身份标识，分层与诊断的基础 |
| 获客数量 | 获客能力评估、获客不足问题判定的核心指标 |
| 到店数量 | 计算到店转化率，构成转化漏斗（获客 → 到店 → 成交） |
| 成交人数 | 计算成交转化率，构成转化漏斗与客群结构分析 |
| 销售额 | 营收规模评估与 Top 门店排名基础；客单价 = 销售额 ÷ 成交人数（自动计算） |

**可选字段**：渠道字段（自然流量 / 线上引流 / 转介绍 / 异业合作 / 线下拓客 / 活动获客）、客群字段（老客 / 会员 / 高客单成交数）、描述字段（门店类型、门店店长）。上传列名可走别名映射自动标准化（见 `utils/config.py` 的 `FIELD_ALIASES`）。

## 🔧 配置与日志

### 业务配置

所有业务参数集中在 `utils/config.py`，应用启动时会自动执行 `validate_config()` 校验配置一致性（字段不重叠、权重和为 1、建议库覆盖完整等），配置改错时页面会给出明确错误提示而非静默异常。

换零售业态（如餐饮）时：替换渠道 / 客群字段与别名映射 → 调整五维模型与建议库文案 → 通过配置校验即可直接使用。

### 日志

- 日志输出到控制台 + `logs/app.log`
- 环境变量 `STORE_DIAG_LOG_LEVEL=DEBUG` 时，侧边栏将显示调试日志面板（日志尾部 30 行），便于联调排查
- 环境变量 `STORE_DIAG_LOG_DIR` / `STORE_DIAG_LOG_FILE` 可覆盖日志目录与文件名
