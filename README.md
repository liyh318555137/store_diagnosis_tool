# 🏪 通用门店多级分层智能诊断系统

一套基于 **Streamlit** 的门店运营诊断工具：上传门店经营数据（CSV / XLSX），系统自动完成**数据清洗 → 指标计算 → 多级分层诊断 → 单店画像分析**全流程，帮助管理者快速定位标杆门店、发现问题门店、识别共性短板，并给出可落地的优化建议。

- **技术栈**：Python 3.12 · Streamlit · Pandas · NumPy · Plotly
- **当前版本**：v0.3.0
- **数据安全**：全部计算在浏览器本地会话中完成，数据不上传任何第三方服务
- **可配置化**：字段体系 / 分层权重 / 诊断规则 / 建议库等全部业务参数集中在 `utils/config.py`，换零售业态只改配置不改代码（详见「八、配置化与复用」）

## 一、核心字段说明

系统以 **5 个输入标准字段** 为诊断核心，上传文件后通过「字段映射」将业务列名对接到标准字段（已按列名自动推荐映射，可手动调整）；**客单价为派生字段，无需上传与映射，由系统自动计算**。

### 必填字段（5 个）

| 标准字段 | 说明 | 用途 |
| --- | --- | --- |
| 门店名称 | 门店身份标识 | 分层与诊断的基础，未映射时无法导入 |
| 获客数量 | 各渠道引流到店前接触到的客户总数 | 获客能力评估、获客不足问题判定 |
| 到店数量 | 实际到店的客户数 | 计算到店转化率，构成转化漏斗 |
| 成交人数 | 实际成交的客户数 | 计算成交转化率，构成转化漏斗与客群分析 |
| 销售额 | 门店营收（元） | 营收规模评估与 Top 门店排名 |

### 派生字段（无需上传与映射）

| 字段 | 说明 |
| --- | --- |
| 客单价 | 清洗阶段按 **销售额 ÷ 成交人数** 自动计算（成交人数为 0 时赋值为 0，避免除零）；用于客群质量评估与高净值识别，分层结果与导出 CSV 中均输出该计算值 |

### 可选扩展字段（映射后自动识别，未映射不影响基础诊断）

| 类别 | 字段 | 说明 |
| --- | --- | --- |
| 渠道字段（6） | 自然流量获客、线上引流获客、转介绍获客、异业合作获客、线下拓客获客、活动获客 | 按获客来源拆分，计算渠道结构 / 丰富度 / 健康度 |
| 客群字段（3） | 老客成交数、会员成交数、高客单成交数 | 按客户类型拆分成交，计算客群结构与质量 |
| 描述字段（2） | 门店类型、门店店长 | 非指标，穿透保留供筛选与明细展示 |

> 💡 **列名别名自动标准化**：上传文件中出现 `线上引流 / 转介绍 / 自然流量 / 异业合作 / 线下拓客 / 活动营销 / 会员人数 / 套购成交数` 等业务列名时，读取后会自动转换为标准字段名，无需手动映射。

## 二、指标体系简介

### 基础转化率（构成「获客 → 到店 → 成交」漏斗）

| 指标 | 口径 |
| --- | --- |
| 到店转化率 | 到店数量 ÷ 获客数量 |
| 成交转化率 | 成交人数 ÷ 到店数量 |
| 总转化率（获客转化率） | 成交人数 ÷ 获客数量 |

### 渠道类指标（有渠道字段时计算）

- **各渠道获客占比**：渠道获客 ÷ 获客总数
- **各渠道贡献销售额**（估算）：渠道获客 × 客单价（未拆分渠道销售额时的替代口径）
- **渠道丰富度**：有有效获客数据的渠道数量
- **优质渠道占比**：转介绍 + 异业合作（高转化、低成本）占获客总数比例

### 客群类指标（有客群字段时计算）

- **各客群成交占比**：老客 / 会员 / 高客单成交数 ÷ 成交人数
- **老客转化率** = 老客成交数 ÷ 到店数量；**新客转化率** =（成交人数 − 老客成交数）÷ 到店数量

### 大盘指标

全部门店汇总：总销售额、总获客、整体到店 / 成交转化率（按总量相除，避免加权口径偏差）、平均客单价、渠道结构、客群结构、等级分布等。

> 所有除法均带除零保护；字段缺失时对应指标自动跳过，**不报错**。

## 三、多级分层模型说明

### 一级：综合分级（五维加权评分，0–100 分）

五个维度按权重加权，指标先 **min-max 标准化到 [0,1]**，维度得分取可用指标的均值：

| 维度 | 权重 | 候选指标（按优先级取第一个可用） |
| --- | --- | --- |
| 营收规模 | 25% | 销售额 |
| 获客能力 | 20% | 获客数量 |
| 转化效率 | 25% | 成交转化率、总转化率 |
| 客群质量 | 15% | 老客成交数占比、会员成交数占比、高客单成交数占比、客单价 |
| 渠道健康度 | 15% | 渠道丰富度、优质渠道占比 |

**分级规则**（按综合得分降序排名分档）：

| 等级 | 排名区间 | 含义 |
| --- | --- | --- |
| S 级 | 前 20% | 标杆门店 |
| A 级 | 20% – 50% | 优秀门店 |
| B 级 | 50% – 80% | 一般门店 |
| C 级 | 后 20% | 落后门店 |

**兼容逻辑**：客群 / 渠道字段整体缺失时对应维度自动失效，剩余维度权重按比例重新分配，保证合计 100%。样本门店少于 5 家时结果仅供参考。

### 二级：标签画像（三类标签）

在综合分级之上，为每家门店打上运营画像标签：

| 标签类别 | 标签 | 判定规则 |
| --- | --- | --- |
| 渠道标签 | 「XX 驱动型」 | 最高渠道获客占比 > 40% |
| 渠道标签 | 「渠道单一型」 | 有效渠道数 ≤ 2 |
| 客群标签 | 「老客复购型」 | 老客成交占比 > 40% |
| 客群标签 | 「高净值型」 | 客单价 > 全店均值 × 1.5 |
| 客群标签 | 「泛客流低效型」 | 转化率低于中位数 **且** 获客高于中位数 |
| 问题标签 | 「获客不足 / 转化低效 / 客单偏低」 | 与全店中位数比较（对极值更鲁棒） |
| 问题标签 | 「渠道畸形」 | 有效渠道 ≤ 1 或最高渠道占比 > 70% |

每个维度得分、综合得分（0–100）、综合排名、门店等级、三类标签均输出为结果列，支持一键导出 CSV。

### 单店自动诊断（与分层联动）

以「与全量数据整体均值对比」为核心（无硬编码阈值）：自动输出**诊断结论**（约 120 字：总分句 + 优势 + 短板 + 特征 + 行动方向）、**核心优势**（如「销售额高于均值 45%」）、**主要问题**（9 条规则引擎 + 高获客低转化复合规则）与 **3 条优化建议**（优先匹配门店标签的建议库，内容可落地）。

## 四、使用说明

### 页面一：数据导入

1. 点击「✨ 加载示例数据」可一键体验完整流程（内置 15 家模拟门店，含渠道 / 客群 / 描述字段与典型异常样本）；
2. 或上传门店数据文件（CSV / XLSX，单文件 ≤ 20MB；CSV 自动识别 UTF-8 / GBK 编码）；
3. 核对「字段映射」：系统已按列名自动推荐，确认 5 个必填字段均已映射（客单价无需映射，由系统按 销售额 ÷ 成交人数 自动计算）；
4. 点击「✅ 确认映射并清洗数据」。

**清洗与异常检测**（自动执行，异常明细可核实）：

- 删除门店名称为空的行；数值字段无法转换 / 无穷值置空并记录；
- **口径修正**：成交人数 > 到店数量（或到店 > 获客）时自动修正到店数量，保证转化率 ≤ 100%，修正记录写入「数据异常标记」列；
- 标记负数、转化率超 100% 等异常值。

### 页面二：分析诊断（三个板块）

1. **一、运营大盘**：4 个核心 KPI 卡片（总销售额 / 总获客 / 整体成交转化率 / 平均客单价）+ 扩展指标卡；转化漏斗图、整体获客渠道结构饼图、销售额 Top5、获客转化率 Top5 柱状图；全部门店核心指标明细表。
2. **二、门店多级分层结果**：按等级 / 门店类型筛选 → 等级统计卡片（S/A/B/C 数量与占比）、等级分布饼图、渠道结构饼图 → 可点击表头排序的明细表（等级彩色徽章 + 渠道 / 问题标签）→ 📥 导出分层结果 CSV（含全部原始字段 + 计算指标 + 分层结果）。
3. **三、单门店画像诊断**：按等级筛选 + 下拉选店（支持「下一个同等级门店」快速切换）→ 基础信息卡片、五维能力雷达图、门店渠道获客结构饼图、关键指标对比卡片（高于 / 低于整体均值）、自动诊断结论与 3 条优化建议，全部联动实时刷新。

## 五、本地运行步骤

### 1. 创建并激活 conda 环境

```bash
# 创建 Python 3.12 环境（环境名可自定义）
conda create -n store_diagnosis python=3.12 -y

# 激活环境
conda activate store_diagnosis
```

### 2. 安装依赖

```bash
# 进入项目目录
cd store_diagnosis_tool

# 安装全部依赖（版本已锁定，见 requirements.txt）
pip install -r requirements.txt
```

### 3. 启动应用

```bash
streamlit run app.py
```

浏览器将自动打开 http://localhost:8501 ；若未自动打开，可手动访问该地址。

> 若使用 Anaconda 且命令行 `python` 无效，请改用 Anaconda 完整路径：`/d/Anaconda/python.exe -m streamlit run app.py`（Windows Git Bash 环境下）。

### 4. 运行测试（维护建议）

```bash
# 安装开发依赖（首次）
pip install -r requirements-dev.txt

# 运行全部测试（26 个用例：配置校验 / 规则引擎 / 单店板块渲染 / 应用端到端冒烟）
/d/Anaconda/python.exe -m pytest -q
```

测试文件亦可直接运行查看演示输出：`/d/Anaconda/python.exe test_diagnosis.py`。

### 5. 日志与调试

- **日志位置**：控制台（stderr）+ `logs/app.log`（滚动文件，5MB × 3 份），记录启动、导入、清洗、分层、诊断各阶段与异常堆栈；
- **环境变量**：
  - `STORE_DIAG_LOG_LEVEL=DEBUG`：输出调试级日志，且侧边栏出现「调试日志」面板（实时查看日志尾部，联调利器）；
  - `STORE_DIAG_LOG_FILE` / `STORE_DIAG_LOG_DIR`：自定义日志文件 / 目录；
- **异常可追溯**：页面所有错误兜底（文件读取失败 / 清洗失败 / 诊断失败）都会同时写入日志堆栈，不再「只见提示、不知原因」。

> Streamlit Community Cloud（share.streamlit.io）可免费托管 Streamlit 应用，支持 GitHub 仓库自动部署。**注意：免费版应用为公开可访问**，请勿上传敏感数据。

```bash

git init

git commit -m "初始化：通用门店多级分层智能诊断系统"

# 关联远程仓库并推送（在 GitHub 上先创建空仓库）
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main
git push -u origin main
```

> `requirements.txt` 已锁定全部依赖版本，Cloud 会自动按此文件安装；`data/example_data.csv` 随仓库一起推送，云端「加载示例数据」功能同样可用。

### 2. 在 Cloud 上创建应用

1. 打开 https://share.streamlit.io ，用 **GitHub 账号**登录并授权；
2. 点击 **「New app」**（或 "Create app"）；
3. 选择：**Repository**（刚推送的仓库）→ **Branch**（main）→ **Main file**（`app.py`）；
4. 若仓库尚未公开，需先在 GitHub 上将仓库设为 **Public**（免费版无法部署私有仓库）；
5. 点击 **「Deploy」**，等待构建完成（首次部署约 1–3 分钟，会自动从 requirements.txt 安装依赖并启动）。

### 3. 高级设置（可选）

- **Python 版本**：进入应用 → **Settings → Advanced settings**，选择 Python **3.12**（与本地验证环境一致）；
- **Secrets**：如需在云端保存 API Key 等敏感配置，在 Settings → Secrets 中以 TOML 格式写入，应用内通过 `st.secrets` 读取（本项目当前不需要）。

### 4. 更新与维护

- **自动更新**：向部署分支 `git push` 新代码后，Cloud 会自动检测变更并重新部署，无需手动操作；
- **手动重启**：在应用页面右上角菜单 → **Rerun / Restart**，或 Settings 中操作；
- **删除应用**：Settings → **Delete app** 即可下线。

### 5. 云端使用注意事项

- **数据不持久化**：上传的数据只保存在当前浏览器会话（`session_state`）中，刷新页面 / 会话过期 / 应用重启后自动清空，每次使用需重新上传；
- **冷启动延迟**：免费版应用空闲后进入休眠，再次访问需等待 30–60 秒冷启动；
- **建议用法**：云端适合演示与团队在线查看；日常批量分析建议在本地运行。

## 八、配置化与复用（换业态指南）

自 v0.3.0 起，**全部业务参数集中在 `utils/config.py` 单一事实源**，其余模块只负责执行逻辑。复用到其他零售业态（餐饮 / 服装 / 美业 / 连锁药店…）**只改配置、不改代码**：

| 配置节 | 内容 | 换业态要改什么 |
| --- | --- | --- |
| 字段体系 | 标准字段、渠道字段、客群字段、列名别名、优质渠道 | 按新业态的业务表头调整（如餐饮：翻台率、桌均消费） |
| 数据导入 | 文件大小上限、最小样本数 | 一般不用改 |
| 分层模型 | 五维名称与权重、S/A/B/C 分档比例、标签阈值 | 权重按经营重点调整（如餐饮更看重客单价与翻台） |
| 诊断引擎 | 9 条诊断规则、问题展示名、建议文案库 | 规则口径与建议话术按业态改写 |
| 应用 / 主题 | 标题、图标、配色 | 品牌化定制 |

**示例：把「客群质量」权重从 15% 调到 25%**（权重合计必须为 1）：

```python
DIMENSIONS = [
    {"name": "营收规模", "weight": 0.25, "candidates": ["销售额"]},
    {"name": "获客能力", "weight": 0.20, "candidates": ["获客数量"]},
    {"name": "转化效率", "weight": 0.25, "candidates": ["成交转化率", "总转化率"]},
    {"name": "客群质量", "weight": 0.25, "candidates": ["老客成交数占比", "会员成交数占比", "高客单成交数占比", "客单价"]},  # 0.15 → 0.25
    {"name": "渠道健康度", "weight": 0.05, "candidates": ["渠道丰富度", "优质渠道占比"]},  # 0.15 → 0.05
]
```

**示例：换渠道体系**（如把「活动获客」换成「外卖平台获客」）：

```python
CHANNEL_FIELDS = ["自然流量获客", "线上引流获客", "转介绍获客", "异业合作获客", "线下拓客获客", "外卖平台获客"]
# 建议库 SUGGESTION_BANK 中同步更新对应渠道的优化建议（validate_config 会强制覆盖齐全）
```

> 🛡️ **改完必跑配置校验**：`/d/Anaconda/python.exe -c "from utils import config; config.validate_config()"`。
> 权重之和不等于 1、字段重叠、别名映射失效、建议库未覆盖新问题名等错误会**立即报错并列出全部问题**，不会静默带病上线；应用启动时也会自动校验，有问题直接提示。

- **时间维度**：接入多期数据，支持环比 / 同比分析、门店经营趋势追踪与异常波动预警；
- **权重可视化配置**：已在 `utils/config.py` 支持权重 / 分档比例配置，后续可在界面开放可视化调整，让业务人员直接改；
- **更多诊断维度**：扩展人效（人均产出）、坪效、成本利润等字段与对应维度、标签（新增维度只需在 `config.py` 的 DIMENSIONS 加一项）；
- **行业基线库**：内置常见行业的指标基准（分位数 / 标杆值），替代「与全店均值对比」的单一口径；
- **智能报告**：一键生成 Word / PDF 格式的经营诊断报告，自动配图与结论摘要；
- **数据连接器**：支持直连数据库 / ERP / 数据中台 API，替代手工上传，实现自动更新诊断。
